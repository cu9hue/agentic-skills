# Where the Unix philosophy came from

**Short version:** the Unix philosophy started as Bell Labs habits in the early 1970s. Doug McIlroy wrote it down in 1978, and later authors turned it into a doctrine. Two things shaped it: one man's pipe idea and very small computers.

## 1. The pipe idea (1964)

On October 11, 1964, Doug McIlroy wrote an internal Bell Labs memo. He said programs should snap together:

> "We should have some ways of connecting programs like garden hose--screw in another segment when it becomes necessary to massage data in another way."

Nobody built it yet. Unix did not exist.

## 2. Unix on small machines (1969–1973)

Bell Labs pulled out of the Multics project in 1969. Multics was large and ambitious. Ken Thompson and Dennis Ritchie then built Unix on a spare PDP-7, and later on the PDP-11. Those machines had very little memory. Small, single-purpose programs were partly a virtue and partly the only option.

McIlroy kept pushing for pipes. In 1973 Thompson said "I'm going to do it" and added pipes to the system. By McIlroy's account, Thompson did not build exactly the design McIlroy had proposed. He built a slightly better one. Overnight, people rewrote their tools as filters that read standard input and write standard output. That shared habit is the core of the philosophy.

## 3. Written down (1978)

The July–August 1978 *Bell System Technical Journal* ran a special Unix issue. McIlroy, E. N. Pinson and B. A. Tague wrote the foreword. It listed the maxims the Unix builders followed:

- Make each program do one thing well. For a new job, build a new program. Don't add features to an old one.
- Expect a program's output to become another program's input. Don't clutter output with extra information.
- Build software to be tried early, and throw away the clumsy parts.
- Use tools, not unskilled help, to lighten a programming task.

McIlroy later put it in three lines (quoted in Peter Salus, *A Quarter Century of Unix*, 1994):

> Write programs that do one thing and do it well. Write programs to work together. Write programs to handle text streams, because that is a universal interface.

## 4. Turned into doctrine (1980s–2000s)

Later writers made it a named school of thought:

- Kernighan and Pike, *The Unix Programming Environment* (1984). This book taught the style to a generation of programmers.
- Rob Pike's rules in "Notes on Programming in C" (1989).
- Mike Gancarz, *The UNIX Philosophy* (1994).
- Eric S. Raymond, *The Art of Unix Programming* (2003). This book gave the 17 "rules" that most people quote today.

**The takeaway:** the philosophy came after the practice. Small machines and McIlroy's pipe idea created the habits. The written rules described what Bell Labs already did.
